# L36 : carte métier (contrat a posteriori)

Pilote : lead (backend L36a, écran L36b, corrections L36c). Relecteurs : w3c (sémantique, confidentialité), scout (UX), doc puis humain.
Origine : demande de Jerem de pouvoir lire et présenter un schéma en zones métier, à partir d'une carte dessinée à la main dans son propre travail. Aucun nom, type ou volume de ce travail n'entre dans le dépôt.
Contrat écrit après coup, d'après les rapports et le code tels que livrés (commits 8d27303, bd36468, c90cd8a, 8e0a038).

## Objectif
Un écran « Carte métier » dessine l'ontologie, ou le modèle cible, en zones métier teintées : types colorés par rôle avec leur volume, relations fléchées, cadres, légende et notes de scénario. L'humain garde la main sur les zones, les rôles, les positions et les scénarios ; la carte ne prétend rien que l'ontologie n'affirme.

## Livrables
1. Backend (L36a), paquet `backend/ontoforge/businessmap/` :
   - graphe neutre issu de l'ontologie ou du PGModel (`graph`) ;
   - volumes (`counts`) : individus distincts du type et de ses sous-classes (fermeture `rdfs:subClassOf`), dans le triplestore local s'il est chargé, sinon dans les individus de l'ontologie ; `null` sans aucune donnée ;
   - rôles déduits de la structure puis corrigeables (`roles`) ; jeu par défaut générique : main, component, hub, lookup, context, reference, document, settings ;
   - zones proposées par cinq stratégies (`zones`) : périmètres, hiérarchie, espaces de noms, communautés, LLM ;
   - cadres suggérés (`frames`) : au moins 2 types qui partagent au moins 2 relations identiques vers les mêmes cibles ;
   - mise en page par recuit simulé en Python pur, positions épinglées respectées, résultat déterministe à graine égale (`layout`) ;
   - état persistant `Project.business_maps` (champ optionnel, rétrocompatible), une carte par source (`ontology` ou `target`).
2. API `backend/ontoforge/api/business_map.py` : `GET` et `PUT /api/projects/{pid}/business-map?source=`, `POST /business-map/suggest-zones`, `/suggest-frames`, `/layout`. Contrat dans `docs/CONTRACTS.md` §13.
3. Écran (L36b) `frontend/src/screens/bmap/`, étape Concevoir, raccourci depuis le Modèle cible :
   - rendu SVG partagé entre l'écran et l'export, thèmes clair et sombre ;
   - zoom, déplacement, survol, inspecteur, épinglage par glisser, panneaux Zones et Scénarios, aperçu puis application des propositions, Réorganiser, Annuler (Ctrl+Z) ;
   - export SVG et PNG ×2 ou ×4 ;
   - mobile en lecture seule ; Krakie connaît l'écran ; étape de visite guidée (21 étapes) ; entrée dans `help_map.json`.
4. Corrections de revue (L36c) :
   - une zone vide est conservée par le serveur, avec un rectangle, et survit à un rechargement ;
   - sémantique : libellés « déclarée dans les deux sens » (inverse) et symétrique à part, « un seul sens retenu pour ce scénario », `owl:disjointUnionOf` ne pose plus `abstract`, bandeaux pour propriétés non dessinées et relations portées par une union de classes ;
   - rôles par défaut génériques avec migration des anciens ids (`LEGACY_ROLES`) ; l'inspecteur dit si le rôle est déduit ou choisi ;
   - mobile : ouverture à 45 % de zoom au moins, bouton « Tout voir ».
5. Documentation : guide utilisateur (section `{#carte-metier}`), api, architecture, limites, glossaire, CHANGELOG (L36b, L36c), fr et en ; captures `carte-metier*.png` fr et en.
