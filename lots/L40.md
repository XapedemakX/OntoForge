# L40 : projets nominatifs et partage collaboratif

Pilote : lead. Relecteurs : secu (revue-securite.md : authentification, cloisonnement, entrées utilisateur), scout (UX du panneau de partage), doc puis humain.
Origine : audit de sécurité du 15/11 (constat SEC-19, dont dépend SEC-03) et décision de Jerem du 15/11 : « on a normalement une page d'authentification, donc projet nominatif. On rajouterait bien le fait de pouvoir partager un projet pour faire du collaboratif. »

## Objectif
Avec l'authentification, chaque projet appartient à un compte, se partage avec d'autres comptes (éditeur ou lecteur) et se modifie à plusieurs sans jamais écraser le travail d'un autre. Sans authentification, tout reste comme avant. Choix par défaut : D-L40-01, que Jerem peut changer.

## Livrables
1. Propriété et cloisonnement (CONTRACTS §16) : propriétaire, liste filtrée, 404 pour un projet inaccessible, contrôle serveur sur toutes les routes à identifiant de projet (table exhaustive `collab/routes.py`, routes de l'assistant à `project_id` dans le corps), test paramétré qui parcourt toutes les routes de l'application.
2. Partage : saisie d'un identifiant existant, rôles éditeur / lecteur, changement de rôle, retrait, transfert de propriété, départ volontaire ; message neutre et limite de 10 recherches par minute.
3. Réglages globaux réservés aux administrateurs (`ONTOFORGE_AUTH_ADMINS`, sinon premier compte) ; vue réduite pour les autres.
4. Mode local inchangé (utilisateur implicite « local »).
5. Migration idempotente des projets sans propriétaire vers le premier administrateur.
6. Collaboratif sans temps réel : ETag / If-Match (409, 428), présence (20 s / 60 s), bandeau de modification, « Recharger et réappliquer », journal d'activité.
7. Front : bouton « Partager », panneau des accès, lecture seule (boutons désactivés, mention), colonnes propriétaire et badge « Partagé », fr et en ; Krakie : entrée `sharing` de `help_map.json`, ancre `partager-un-projet`.
8. Documentation : CONTRACTS §16, guide utilisateur (section « Partager un projet » + captures), api, limites, glossaire, changelog (fr et en), `journal/L40/rapport.md`.

## Critères d'acceptation
- `cd backend && pytest -q` vert, dont `tests/test_collab.py` (cloisonnement de toutes les routes par rôle, partage, transfert, migration, conflit 409, 428, présence, réglages réservés aux administrateurs, mode local).
- `cd frontend && npm run build` sans erreur.
- `BACKEND_PORT=8987 FRONT_PORT=4987 node tools/recette/l40_partage.mjs` : deux comptes, A crée, B ne voit pas, A partage en lecteur, B en lecture seule, A passe B éditeur, B modifie, conflit, présence des deux côtés ; captures fr / en, clair / sombre.
- Recettes existantes (mode local) inchangées : `e2e_ui.mjs` 30/30, `tour.mjs`, `english_scan.mjs` à 0, `test_help_map`, `test_docs_bilingual` verts.
- Hors périmètre : montées de dépendances reportées (D-L21-02) ; liaison secret ↔ hôte (SEC-03, L39-secu-b).
