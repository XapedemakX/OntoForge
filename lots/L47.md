# L47 : dossier de justification et arbitrage par racine de hiérarchie

Pilote : lead. Origine : carnet d'idées P-05, P-01, P-02 (top 5 du 4/11), « lance le tout » de Jerem du 16/11. Rapport : `journal/L47/rapport.md`.

## Objectif
1. **Arbitrage par racine (P-01, P-02).** Les constats sans vrai choix (une seule option, ou option recommandée sans perte) passent en `auto` et ne sont plus comptés « à arbitrer » ; dans l'écran Arbitrer, regroupement par racine de hiérarchie avec « appliquer à toute la branche » ; champ « pourquoi » (raison en une ligne) enregistré avec chaque décision. Les constats `lost` restent toujours à arbitrer par l'humain (D-L14-02). Compatibilité des `decisions.json` existants (ancien format = choix sans raison).
2. **Dossier de justification (P-05).** Export HTML et Markdown par cible : modèle retenu, ce qui est perdu, compensé, décidé par qui (compte), quand et pourquoi, recommandations non suivies. Bouton dans Exports ; route `GET /projects/{id}/justification/{target}?format=md|html` (lecture, droits lecteur) ; HTML autonome sans script.
3. Doc fr/en (guide, CHANGELOG, help_map de Krakie), i18n, contrat `docs/CONTRACTS.md` (nouvelle section), décision tracée.

## Critères d'acceptation
pytest vert (nouveaux tests : reclassement auto, branche, raison, dossier md/html, rétrocompatibilité) ; sur l'exemple automaint, décisions humaines nécessaires < 25 (mesure dans le rapport) ; `npm run build` ; recette `BACKEND_PORT=9147 FRONT_PORT=5147 node tools/recette/l47_justification.mjs` (nouvelle) + `e2e_ui` 30/30 + `mobile_l44`. Relecteurs : curiosity + neo4j (sens des pertes), scout (UX), secu (export HTML : échappement), doc.
