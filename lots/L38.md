# L38 : Krakie dans les Paramètres

Pilote : lead (assistant, front). Relecteurs : scout (UX), doc puis humain.
Origine : demande de Jerem du 15/11 : « je veux que Krakie soit également disponible dans les paramètres pour aider à configurer ».

## Objectif
Krakie est présente sur l'écran Paramètres (route globale, sans projet) et aide à configurer OntoForge : elle explique, diagnostique et recommande, y compris au premier lancement quand aucun LLM n'est branché. Elle ne modifie aucun réglage et ne voit jamais un secret.

## Livrables
1. Front : aquarium et panneau montés sur `#/parametres` sans projet ; mode « paramètres » (pas d'actions de modèle, pas de contexte projet) ; contexte d'écran = onglet affiché (fournisseurs LLM, langues, valeurs par défaut, versions, affichage, endpoints SPARQL) et suggestions par onglet ; conversation propre à l'écran.
2. Backend : `POST /api/assistant/chat` accepte `project_id` absent pour `context.screen = settings` (CONTRACTS §14, D-L38-01) :
   - instantané non sensible de la configuration (fournisseurs, modèles, URL nettoyées, langues, défauts, versions, endpoints) ;
   - réponses déterministes par onglet sans LLM (mock ou non configuré) : pas à pas Anthropic, compatible OpenAI, Ollama, endpoint SPARQL, versions, langues, valeurs par défaut, affichage, avec diagnostic et lien vers la doc ;
   - avec un fournisseur réel, le LLM reçoit l'instantané et ses actions sont revalidées ; s'il échoue, réponse intégrée ;
   - jamais de clé d'API, de mot de passe ni de jeton, ni dans le contexte envoyé au LLM, ni dans la réponse (masquage des secrets enregistrés et des formes usuelles de clés).
3. Cartes d'actions : « Aller à cette section » (onglet, défilement, mise en évidence), « Tester la connexion » (routes de test existantes, sur ce qui est enregistré), « Ouvrir l'aide » (`help_map.json`, ancres par onglet dans `docs/guide/utilisateur(.en).md`). Aucun réglage n'est modifié sans clic explicite de l'utilisateur.
4. Aide : « ? » et carte d'aide ouvrent la section de l'onglet affiché ; le guide s'ouvre sans projet (`#/aide/<page>/<ancre>`).
5. i18n fr et en, guide utilisateur fr/en (sous-sections par onglet + « Krakie dans les Paramètres », captures `krakie-parametres` fr/en), API, limites, CHANGELOG fr/en, CONTRACTS §14, journal.

## Critères d'acceptation
- `cd backend && pytest -q` : tout vert, dont `tests/test_settings_assistant.py` (32 cas : réponses par onglet et par type de fournisseur, fr et en, diagnostic, cartes et identifiants validés, secrets absents du contexte LLM et de la réponse, réglages inchangés, repli quand le LLM échoue) et `tests/test_help_map.py` (ancres des six onglets, fr et en).
- `cd frontend && npm run build` OK.
- Recette `BACKEND_PORT=8983 FRONT_PORT=4983 node tools/recette/l38_settings_krakie.mjs` : Paramètres sans projet, Krakie visible, question sur le LLM en mode mock (pas à pas + cartes), « Aller à cette section », « Ouvrir l'aide », « ? », fausse clé enregistrée puis aucune trace dans les requêtes et réponses `/api/assistant`, réglages inchangés, aquarium sans recouvrement, anglais ; captures clair / sombre, desktop / mobile dans `journal/L38/screens/`.
- `e2e_ui.mjs` 30/30, `tour.mjs`, `english_scan.mjs` sans suspect, `test_docs_bilingual` vert.

## Hors périmètre
- Aucune modification de réglage par Krakie (hors du lot par principe).
- Le prompt `[TASK:settings]` n'est pas éprouvé sur un vrai fournisseur (pas de réseau en test).
- `GET /api/settings` renvoie les URL telles que saisies : un identifiant collé dans une URL reste visible dans l'écran (signalé, non corrigé ici).
