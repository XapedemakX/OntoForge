# L16 - Assistant global Krakie

## Livré
- **Backend** : `assistant/agent.py` (nouveau), `api/assistant.py` (`context` sur `/chat`, `POST /assistant/shapes/apply`), CONTRACTS §4 (ajouts). Réponse `{reply, actions[{kind, payload, summary}], warnings}` ; actions `ops | proposal | shapes | guided_query | navigate`. Le prompt système reçoit l'écran, la sélection détaillée (classe avec ses propriétés et restrictions, shape, propriété), les données de l'écran (`extra`, ex. requête courante) et un schéma compact (IRI de base, classes, propriétés).
- **Validation stricte** : opérations rejouées une à une sur une copie du projet (`editing/ops.apply_ops`), la fautive est retirée avec un avertissement ; références résolues par IRI, nom local ou libellé (sinon retrait : rien d'inventé) ; toute nouvelle entité prend l'IRI de base du projet ; opérations de présentation refusées ; shapes revalidées (classe, propriété, entiers, motif) ; requêtes guidées via `queries/nl` (sanitize) + `build_all`.
- **Repli sans LLM** (mock / non configuré) : ajoute la classe X [sous Y] [avec une propriété p [en unité] [de type T]], ajoute la propriété p à X (ou « cette classe » = sélection), rends p obligatoire, supprime X, contrainte min/max/motif sur p dans la shape S, cherche les X dont … (-> /query/nl), ouvre les shapes. Sinon ancien chat (proposition automobile du mock).
- **Front** `frontend/src/assistant-global/` : `AssistantDock` (Krakie flottante en bas à droite, Ctrl+K, panneau latéral redimensionnable à la souris et au clavier, plein écran < 900 px, reste ouvert d'un écran à l'autre), ligne « Contexte : [écran] [sélection] » avec retrait de la sélection ou de tout le contexte, puces de suggestions (celles de l'écran sinon par défaut), choix du fournisseur, `ActionCards` (aperçu en français, Appliquer -> POST /ops, Annuler -> /ops/undo tant que c'est la dernière modification, Voir dans l'éditeur, Ouvrir dans Requêtes, shapes), conversation partagée avec l'écran Assistant (`store.ts`, même clé localStorage que L10, l'écran plein écran utilise `useConversation` et `runChat`). Krakie réfléchit / contente / inquiète. Montage dans `shell/Shell.tsx` (une ligne) ; l'éditeur et le tableau de bord déclarent leur contexte (`useAssistantContext`). Clés `ag.*` fr/en.
- **Tests** : `backend/tests/test_assistant_context.py` (8 tests sur automaint avec le mock : classe + propriété en bar, parent inconnu, propriété, obligatoire, suppression, shape + annulation, requête guidée, navigation, opérations LLM invalides retirées, compatibilité sans contexte). Suite : 566 verts. `npm run build` vert.
- **Playwright** : `tools/recette/l16_assistant.mjs` (Ctrl+K dans l'éditeur -> « ajoute la classe Pneu sous Pièce avec une propriété pression en bar » -> aperçu -> Appliquer -> Pneu dans le graphe -> Annuler ; tableau de bord -> requête guidée -> Requêtes ; mobile 390 px sans défilement horizontal). Captures `journal/L16/screens/01..06`.

## Mode d'emploi pour les écrans
1. Déclarer le contexte : `useAssistantContext({ screen: 'shapes', projectId: p.id, target, selection: sel ? { kind: 'shape', id: sel.id, label: sel.name } : null, extra: { filtre }, suggestions: ['Ajoute une contrainte min 1 sur …'] }, [sel?.id, filtre])`. Noms d'écran reconnus pour la route : dashboard, editor, ontology-list, shapes, shacl, conformance, analysis, model, exports, queries (autres : le contexte est ignoré tant que `screen` ne correspond pas à la route). `selection.kind` : class, prop, shape, finding, query ; `selection.id` = IRI (classe / propriété) ou id de shape ; `extra` doit rester compact (< 3 Ko, la requête guidée courante pour Requêtes).
2. Bouton Krakie contextuel : `<Button size="sm" icon="wand-magic-sparkles" onClick={() => openAssistant({ prompt: 'Ajoute une propriété à cette classe', send: false, context: { selection: { kind: 'class', id: iri, label } } })}>Krakie</Button>` ; `send: true` envoie directement. Le contexte ponctuel est fusionné au contexte déclaré pour ce message.
3. Requêtes : l'action « Ouvrir dans Requêtes » écrit `localStorage['ontoforge.pending-query.<projectId>']` (réponse /query/nl : `guided`, `sparql`, `question`, `explanation`…) et émet l'évènement window `ontoforge:open-query` (detail = même objet) avant de naviguer vers `#/projet/<id>/requetes`. L'écran Requêtes doit charger `payload.guided` dans le constructeur guidé au montage (lire puis supprimer la clé) : **à brancher par l'agent Requêtes**.
4. Rafraîchissement : après Appliquer, `setP(project)` et l'évènement `ontoforge:project` sont émis ; les écrans qui gardent une copie locale doivent l'écouter.

## Limites
- Prompt LLM non éprouvé sur un vrai fournisseur (pas de réseau) : le JSON est validé strictement, une réponse non JSON s'affiche comme simple texte.
- L'historique d'annulation est linéaire : « Annuler » n'est offert que pour la dernière modification appliquée.
- Le repli déterministe ne comprend que les tournures listées ; « min n » sur une propriété numérique ou date devient une borne de valeur (min_inclusive), sinon un nombre de valeurs (min_count).
- Le panneau recouvre la partie droite de l'en-tête (cible, périmètre) quand il est ouvert.
- Écrans refaits par d'autres agents (liste, shapes, requêtes) : pas encore de contexte déclaré, seul le contexte de base (écran) est envoyé.
